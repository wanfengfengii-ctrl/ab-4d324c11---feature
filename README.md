# 复合材料铺层序列修复工作台

纯前端（TypeScript + React）的铺层修复工具：工程师在浏览器中导入或编辑参考铺层，
启动综合后逐位比较原序列与修复结果。解析、求解、复核全部在浏览器内完成，
**不调用任何业务后端**。

## 规则与求解

合法序列须满足：4–48 偶数层；角度 ∈ {0°, +45°, −45°, 90°}；修复后保持各角度数量；
关于中面对称；+45° 与 −45° 等量；表面层非 90°；相邻角差（按 180° 周期计）≤ 45°；
同角连续 ≤ 3 层。

求解器利用对称性对首半做动态规划，**全局**依次最小化：

1. 一级目标：改动位置数；
2. 二级目标：相邻角度变化次数；
3. 并列时按 0° → +45° → −45° → 90° 的规定次序取字典序最小方案。

不是局部交换，也不是首个可行排列。页面展示两级目标值、逐层差异，以及每条规则的
可复核证据；输入非法或确实无解时会清除旧结果并列出对应原因。

## 返工工艺条带（条带模式）

返工时局部已完成预压的连续铺层应尽量作为**完整工艺条带**保留。在参考铺层卡片下方开启
条带模式后，工程师可在**参考铺层首半区间**内选定 1–3 条、长度 2–4 层的条带：

- 每条条带的角度顺序必须在修复结果**首半**中完整、连续出现（镜像半自然逆序复现）；
- 多条条带的**采用位置彼此不得重叠**（原始区间允许相交，落位由求解器裁决）；
- 全板仍须满足数量守恒、对称、平衡、表面与相邻过渡等全部既有规则。

条带落位与两级目标、字典序在**同一次全局搜索**中联合裁决（条带进度是 DP 状态的一部分），
不是"先生成原修复方案再筛选条带"。结果区逐条显示：原始区间、修复后采用区间、中面镜像
位置，以及采用/镜像区间的逐层角度证据；条带无法共同放置时清除旧结论并说明阻断原因。
编辑条带、参考铺层或切换模式都会立即撤下旧综合结果。关闭条带模式时，求解与展示语义
与原先完全一致（输出与编号回到无条带版本）。

## 本地开发

```bash
npm install
npm run dev      # 开发服务器
npm test         # 求解器测试（含暴力枚举交叉验证）
npm run build    # 类型检查 + 产出 dist/
```

## Docker 运行（静态 Web）

```bash
docker compose up -d web                 # 默认宿主机端口 8080
WEB_PORT=9000 docker compose up -d web   # 自定义宿主机端口
curl http://localhost:8080/health        # 健康检查
```

## 验收服务 verify

`verify` 服务先运行求解器测试套件（单元测试 + 暴力枚举对照 + n=48 性质测试），
再对 `web` 服务做 HTTP 冒烟检查（/health 与首页内容）：

```bash
docker compose up --exit-code-from verify --abort-on-container-exit verify
```

退出码为 0 表示验收通过。

## 输入格式

- 记号串：`0, +45, -45, 90, 90, -45, +45, 0`（逗号/空白/分号分隔，`45` 等同 `+45`）
- JSON 数组：`[0, "+45", "-45", 90]`
- 或直接在页面逐层下拉编辑、导入 `.txt` / `.json` / `.csv` 文件
